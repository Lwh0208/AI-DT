# smart_reply_assistant

高仿真数字孪生回复助手系统 — 为固定使用者"zzx"构建的生产级本地智能回复预测引擎。

## 系统概述

本系统通过分析历史聊天数据，自动沉淀多角色的原生画像与主题记忆；在运行阶段结合多方画像、当前聊天窗口最近 20 条上下文消息及历史经验，高精度预测zzx的回复；并在模拟一天结束时进入 Dream 模式完成状态自我反思与数据的增量演进，使助手的回复行为无限接近本人。

## 后续计划

项目将从“单用户数字孪生回复预测”逐步扩展为团队级 Multi-Agent 协作助手。目标不是简单复制个人口吻，而是在获得成员授权、严格隔离数据和保留人工确认的前提下，让系统理解团队成员的职责、专业领域和协作关系，为知识性、领域性问题生成更准确的候选回复。

### 1. 团队级 Multi-Agent 架构

- 为每位团队成员创建独立的 Personal Agent，分别管理其表达风格、职责边界、领域知识、长期记忆和会话状态。
- 增加 Team Orchestrator，根据发送者、接收者、聊天窗口、问题领域和成员在线状态，将请求路由给最合适的 Personal Agent。
- 支持一个问题由多个领域 Agent 协作处理，例如研发 Agent 提供技术判断、产品 Agent 补充背景、项目 Agent 汇总进度，最终由目标成员的 Agent 统一组织回复。
- 将“回复生成”拆分为意图识别、知识检索、专家选择、候选回复生成、风险检查和人工确认等可观测阶段。

### 2. 画像隔离与权限边界

- 为每位成员建立独立的画像、记忆、经验和上下文命名空间，默认禁止跨成员读取。
- 将信息划分为个人私有、点对点共享、项目组共享和团队公开四级，检索前先进行权限判断。
- 画像只沉淀稳定的工作偏好、表达习惯和职责信息，不把临时情绪、敏感聊天或未经确认的推断固化为长期事实。
- 支持成员查看、修正、冻结和删除自己的画像与记忆，并记录每次更新的来源、时间和版本。
- 对跨画像信息引用提供可追溯依据，避免模型把 A 私聊中的内容泄露给 B。

### 3. 团队知识图谱与领域记忆

- 从项目文档、会议纪要、任务记录和授权聊天中抽取“成员—项目—职责—技术—决策—时间”关系，构建团队知识图谱。
- 将稳定事实存入知识图谱，将过程性讨论存入带时间与来源的情景记忆，避免过期结论长期生效。
- 建立实体消歧和版本机制，识别项目别名、人员简称、方案变更与决策失效时间。
- 回复时同时检索个人画像、当前会话、项目知识和历史决策，并返回内部证据链与置信度。
- 对知识冲突采用“最新有效来源优先 + 人工确认”，不让模型自行覆盖高可信事实。

### 4. 点到点精准预测与协作路由

- 学习同一成员面对上级、同级、跨部门和外部合作方时不同的表达方式，而不是只生成统一口吻。
- 在单聊中结合双方关系与历史上下文，在群聊中结合成员职责、被提及对象和当前讨论主题判断是否需要回复。
- 增加领域分类器和专家能力索引，将技术、产品、运营、项目管理等问题路由到对应知识 Agent。
- 当目标成员不是最佳回答者时，系统给出“建议转交给谁”或生成多人协作草稿，而不是强行代答。
- 支持候选回复排序，综合内容正确性、身份一致性、关系适配度、信息充分度和风险等级选择最佳草稿。

### 5. 安全治理与人工确认

- 默认只生成候选回复，不自动发送；逐步开放低风险、可撤回场景的自动化能力。
- 对承诺、审批、合同、财务、权限、生产变更、人事和外部披露等高风险意图强制熔断并转人工确认。
- 在发送前执行隐私泄露、越权引用、错误承诺、幻觉事实和不当语气检查。
- 为每次预测保存使用了哪些画像、知识节点和上下文的审计记录，但不在普通回复中暴露内部隐私。
- 引入成员授权、数据保留周期、数据导出与删除机制，确保系统只学习有合法来源和明确用途的数据。

### 6. 反馈学习与效果评测

- 将“候选回复—人工修改—最终发送内容”作为显式反馈，区分事实错误、语气偏差、遗漏信息和决策越界。
- Dream 模式从单用户日终反思扩展为个人反思与团队知识更新两条链路，避免把个人风格误写入公共知识。
- 建立离线回放评测集，持续跟踪回复命中率、编辑距离、事实准确率、知识引用正确率、隐私泄露率和人工接管率。
- 对新画像、新 Prompt、新模型和新路由策略进行版本化 A/B 测试，出现退化时可以回滚。
- 通过难例池积累跨项目、多人协作、信息冲突和长时间跨度对话，重点提升系统边界场景的稳定性。

### 7. 工程化与部署演进

- 将当前本地流水线拆分为画像服务、记忆服务、知识检索、Agent 编排、策略检查和评测服务。
- 增加消息平台适配层，以统一事件格式接入单聊、群聊、文档、任务和会议纪要等来源。
- 支持本地模型与私有化部署，敏感画像和聊天原文默认不离开受控环境。
- 引入增量索引、缓存、异步任务和可观测性，记录延迟、token 消耗、Agent 路由和失败原因。
- 提供团队管理界面，用于成员授权、画像审阅、知识纠错、风险规则配置和运行质量监控。

### 阶段性里程碑

- **M1：多用户隔离。** 完成成员配置化、独立画像目录、权限校验和单聊路由。
- **M2：团队知识增强。** 接入项目文档与会议纪要，完成知识图谱原型和可追溯检索。
- **M3：Multi-Agent 协作。** 上线 Team Orchestrator、领域 Agent 和候选回复排序。
- **M4：安全试运行。** 在人工确认模式下进行小范围团队试点，建立评测集和审计机制。
- **M5：受控自动化。** 仅对低风险、高置信度场景开放自动发送，并持续监控和回滚。

## 两阶段数据分离设计

系统严格区分两种数据源：

| 数据类型 | 目录 | 用途 | 何时使用 |
|---------|------|------|---------|
| 历史数据 | `data/history/` | 初始化画像与记忆 | 首次运行或重建画像 |
| 测试数据 | `data/test/` | 模拟运行与反思 | 每次模拟测试 |

- **历史数据**只在画像初始化阶段读取，用于让 LLM 从充足的历史行为中抽取角色特征；多个文件会按聊天窗口分块注入，避免不同私聊被混成同一条会话
- **测试数据**在模拟运行阶段按聊天窗口逐文件处理，触发回复预测、即时反思和 Dream 模式；当前窗口的最近上下文会独立记录
- 两种数据互不干扰，可以独立更新

## 快速开始

### 1. 安装依赖

```bash
cd smart_reply_assistant
pip install -r requirements.txt
```

### 2. 配置环境

```bash
cp .env.example .env
# 编辑 .env 填入实际 LLM API 地址和 Token
```

### 3. 准备数据

**历史数据**（`data/history/`）：放入较多量的历史聊天记录，用于初始化画像。格式示例：

```
zzx 2025/9/1 12:01:56
赵博，啥情况

zy 2025/9/1 14:10:05
毕然他们好像要投资源，本地部署GLM5
```

**测试数据**（`data/test/`）：放入需要模拟运行的对话记录。推荐按窗口类型放到 `单聊/` 和 `群聊/` 子目录；缺失年份会自动补 2026：

```
data/test/
├── 单聊/
│   ├── lwh.txt
│   └── zy.txt
└── 群聊/
    └── project_group.txt
```

直接放在 `data/test/` 根目录下的 `.txt` 会按单聊兼容处理。单聊中所有非zzx消息都会触发模拟回复；群聊中只有提及zzx或其别名的消息才触发模拟回复。

```
lwh 4/10 09:15:00
@zzx 昨天的测试环境问题解决了吗？
```

支持的完整格式列表：
- `发送者 2025/9/1 12:01:23` → 保留原始年份 2025
- `发送者 4/22 18:12:10` → 自动补全为 2026 年
- `[2026-01-15 10:30:22] 发送者: 消息内容` → 同行格式
- `[图片]`、`[文件]` 等特殊内容正常识别

### 4. 运行系统

```bash
# 完整运行（初始化 + 模拟）
PYTHONPATH=. python -m src.app --verbose

# 仅初始化画像（不运行模拟）
PYTHONPATH=. python -m src.app --init-only

# 指定自定义数据目录
PYTHONPATH=. python -m src.app --history-dir /path/to/history --test-dir /path/to/test
```

### 5. 运行测试

```bash
PYTHONPATH=. pytest tests/ -v
```

## 关键设计约束

- 所有结构化 Markdown 严禁使用表格语法，统一使用多级标题和无序列表
- 任一角色画像初始化失败时，程序会停止，并清理本次运行新增的 profiles/runtime 残留
- 单聊中所有非张照西消息都会触发回复预测
- 群聊中只有提及zzx/zx/西哥的消息才触发回复预测
- zzx主动发起的消息和真实回复会进入当前窗口上下文，但不会触发预测
- 完整运行结束后会生成 `runtime/transcript_*.txt`，用于查看测试消息、预测回复、真实回复对照
- 日期变更时强制触发 Dream 模式
- 更新时间为对话时间而非真实时间
